## M2. 정답 판정 로직과 문제 검증 — 2026-10-10

**결정한 것**
- 3단계 "고칠 곳 없음" 문제는 `"noError": true`로 표시한다. `wrong`과 `correct`가 같고 `target`·`choices`는 넣지 않는다. 기획서 8.1 표에 반영
- 샘플 30문제 중 "고칠 곳 없음"은 5문제
- `target.start`는 `wrong`에서 0부터 센 글자 위치. 문장 길이 상한에는 띄어쓰기·문장 부호도 센다

**한 일**
- 문제 타입·태그 목록·길이 상한: `src/judge/types.ts` (태그는 기획서 4.2 그대로)
- 정규화: `src/judge/normalize.ts` (NFC, 앞뒤 공백 제거, 연속 공백·탭·전각 공백을 한 칸으로)
- 판정 순수 함수: `src/judge/judge.ts`
  - `judgeFix(problem, replacement)`: 맞춤법·문장 부호 고치기. 보기 선택과 직접 입력을 같은 함수로 판정(틀린 부분을 바꿔 넣은 문장이 acceptedAnswers 중 하나와 같으면 정답)
  - `judgeTap(problem, tapStart, tapEnd)`: 틀린 낱말 찾기. 탭한 범위(글자 하나 또는 어절)가 target과 겹치면 정답
  - `judgeNoError(problem)`: "고칠 곳 없음" 버튼
  - `judgeSpacing(problem, answer)`: 띄어쓰기. 글자 사이 띄움/붙임 비교, 틀리면 가장 가까운 정답 기준으로 `needSpace`(띄워야 할 곳)·`needJoin`(붙여야 할 곳) 위치를 돌려줌
- 검증 모듈: `src/judge/validate.ts` (`validateProblem`, `validateProblems`). M7 AI 생성에서도 그대로 쓴다
  - 필수 필드·값, 태그가 그 단계 목록에 있는지, 글자가 정규화되어 있는지, 단계별 길이 상한, acceptedAnswers에 correct 포함
  - 맞춤법·문장 부호: wrong ≠ correct, target.start 위치의 글자 = wrongText, target 밖은 정답 문장과 같음(오류 한 곳), choices 중복 없음·정답 정확히 1개
  - 띄어쓰기: 공백 말고 글자가 같음, target·choices 없음
  - 고칠 곳 없음: 3단계만, wrong = correct, target·choices 없음
  - id 중복(파일을 넘어서도)
- 검증 스크립트: `scripts/validate-problems.ts`, `npm run validate`. 문제점을 `[파일] id: 내용`으로 출력하고 실패 코드(1)로 끝남
- 개발 도구 추가: `tsx`(스크립트 실행), `@types/node`(스크립트 타입 검사). `tsconfig.json`에 `scripts` 포함

- 검수표: `docs/문제 검수표 M2.md`

## M8. 공유 코드·QR, 교사용 안내 — 2026-10-11

**결정한 것**
- 측정해 보니 한글 문제는 압축이 잘 안 돼, **30문제(약 3,300자)는 QR 한 장에 들어가지 않는다.** 5문제만 담아도 QR 버전 20(97×97칸)이라 교실 뒤에서는 찍기 어렵다
  - 그래서 **링크 중심**으로 했다. 링크는 30문제까지, QR은 버전 20 이하(약 5문제)일 때만 보여 주고, 30문제를 넘으면 JSON 파일 내보내기·불러오기
- 압축: `lz-string` 대신 브라우저 내장 deflate(`CompressionStream`). 약 20% 짧고 라이브러리가 필요 없다. 기획서 10.1·13장을 고쳤다
- 학생 기기: 불러온 세트는 지도에 **"선생님 문제"** 스테이지로 나온다. 불러오면 바로 한 판이 시작된다. 한 번에 한 세트만 두고, 새로 불러오면 바뀐다. 별·오답 노트·도감은 평소처럼 남는다

  - 설명 창이 떠 있는 동안은 답한 몬스터를 다음 웨이브로 넘어가도 그린다(`BattleScreen.tsx`의 `visible`)
