## M1. 프로젝트 생성과 16:9 화면 틀 — 2026-10-10

**한 일**
- React 18.3 + Vite 6.4 + TypeScript 5.9 프로젝트를 직접 구성(Vite 기본 템플릿은 React 19라서 쓰지 않음)
- 테스트 도구: Vitest 5.0.3(처음 설치한 3.2에 보안 권고가 있어 올림, `npm audit` 0건), Playwright 1.64(컴퓨터에 설치된 Chrome 사용)
- 기획서 10.2 폴더 구조 생성(빈 폴더는 `.gitkeep`)
- 16:9 무대: `src/components/Stage.tsx`, 비율 계산 `src/components/stageFit.ts`. 1920×1080 좌표로 배치하고 창 크기에 맞춰 통째로 확대·축소, 남는 곳은 어두운 여백
- 시작 화면 `src/screens/StartScreen.tsx`: 제목, 시작하기, 전체 화면 버튼(지원하지 않는 브라우저에서는 숨김)
- 수비전 임시 배치 `src/screens/BattleScreen.tsx`: 레인 3줄, 임시 몬스터 3마리와 말풍선, 성문, 수비대원 자리, 위쪽 정보 막대(성벽 체력, 웨이브, 마나, 속도 버튼), 아래쪽 문장 카드(보기 버튼 3개, 동작 없음)
- 임시 그림은 모두 `src/components/PlaceholderArt.tsx` 한 곳에 모음(M5에서 이 파일만 바꾸면 됨)
- 글꼴: Pretendard(npm 패키지, 필요한 글자 조각만 내려받는 dynamic subset)
- 크기 기준: 무대 좌표로 문장 카드 56px·보기 44px, 버튼 높이 80~110px. 1366×650에서도 문장 카드 글자 실제 약 34px, 버튼 실제 48px 이상

**확인 결과**
- `npm test`: 5개 통과(무대 비율 계산)
- `npm run build`: 통과
- `npm run test:e2e`: 4개 통과. 1920×1080, 1536×864, 1366×768, 1366×650(주소창 때문에 실제 보이는 크기)에서
  - 시작 화면·수비전 요소가 무대 밖으로 나가지 않음
  - 버튼 실제 크기 48px 이상, 문장 카드 글자 실제 24px 이상, 문장이 카드 밖으로 넘치지 않음
- 스크린숏: `docs/screenshots/M1/` (start-*, battle-* 각 4장)

**남은 일·알려진 문제**
- 몬스터 말풍선 글자는 1366×650에서 실제 약 18px로 작다. 말풍선은 미리보기이고 문제는 문장 카드에서 읽으므로 M3에서 말풍선을 짧게 할지 함께 정한다.

- 실제 디벗 기기에서는 아직 확인하지 않았다(배포 뒤 M5에서 확인).

**다음 단계(M2)에서 먼저 볼 파일**

## M2. 정답 판정 로직과 문제 검증 — 2026-10-10

**결정한 것**
- 3단계 "고칠 곳 없음" 문제는 `"noError": true`로 표시한다. `wrong`과 `correct`가 같고 `target`·`choices`는 넣지 않는다. 기획서 8.1 표에 반영
- 샘플 30문제 중 "고칠 곳 없음"은 5문제
- `target.start`는 `wrong`에서 0부터 센 글자 위치. 문장 길이 상한에는 띄어쓰기·문장 부호도 센다

**한 일**
- 문제 타입·태그 목록·길이 상한: `src/judge/types.ts` (태그는 기획서 4.2 그대로)
- 정규화: `src/judge/normalize.ts` (NFC, 앞뒤 공백 제거, 연속 공백·탭·전각 공백을 한 칸으로)
- 판정 순수 함수: `src/judge/judge.ts`
  - `judgeFix(problem, replacement)`: 맞춤법·문장 부호 고치기. 보기 선택과 직접 입력을 같은 함수로 판정(틀린 부분을 바꿔 넣은 문장이 acceptedAnswers 중 하나와 같으면 정답)
  - `judgeTap(problem, tapStart, tapEnd)`: 틀린 낱말 찾기. 탭한 범위(글자 하나 또는 어절)가 target과 겹치면 정답
  - `judgeNoError(problem)`: "고칠 곳 없음" 버튼
  - `judgeSpacing(problem, answer)`: 띄어쓰기. 글자 사이 띄움/붙임 비교, 틀리면 가장 가까운 정답 기준으로 `needSpace`(띄워야 할 곳)·`needJoin`(붙여야 할 곳) 위치를 돌려줌
- 검증 모듈: `src/judge/validate.ts` (`validateProblem`, `validateProblems`). M7 AI 생성에서도 그대로 쓴다
  - 필수 필드·값, 태그가 그 단계 목록에 있는지, 글자가 정규화되어 있는지, 단계별 길이 상한, acceptedAnswers에 correct 포함
  - 맞춤법·문장 부호: wrong ≠ correct, target.start 위치의 글자 = wrongText, target 밖은 정답 문장과 같음(오류 한 곳), choices 중복 없음·정답 정확히 1개
  - 띄어쓰기: 공백 말고 글자가 같음, target·choices 없음
  - 고칠 곳 없음: 3단계만, wrong = correct, target·choices 없음
  - id 중복(파일을 넘어서도)
- 검증 스크립트: `scripts/validate-problems.ts`, `npm run validate`. 문제점을 `[파일] id: 내용`으로 출력하고 실패 코드(1)로 끝남
- 개발 도구 추가: `tsx`(스크립트 실행), `@types/node`(스크립트 타입 검사). `tsconfig.json`에 `scripts` 포함
- 3단계 샘플 30문제: `src/data/problems/level3-sample.json` (보조 용언 태그는 허용 규정 때문에 뺌, 9개 태그에 3~4문제씩, 모두 `builtin`·`reviewed: false`)
- 검수표: `docs/문제 검수표 M2.md`

**확인 결과**
- `npm test`: 58개 통과(판정 28, 검증 25, 무대 비율 5). NFD 한글, 문장 끝 공백, 연속 공백, 복수 정답, 문장 부호 앞 띄어쓰기, 빈 입력 포함
- `npm run validate`: 파일 1개, 문제 30개 통과. 일부러 망가뜨린 파일(위치 틀림, 보기에 정답 없음, id 중복)을 넣었을 때 문제점 5개를 출력하고 실패 코드로 끝나는 것도 확인
- `npm run build`: 통과
- `npm audit`: 0건

**남은 일·알려진 문제**
- 샘플 30문제 선생님 검수(`docs/문제 검수표 M2.md`). 확신 낮음: L3-matchi-003
- 맞히다/맞추다 태그의 근거: 기획서 4.2는 "제57항"이지만 제57항 목록에는 '마치다/맞히다'만 있는 것으로 보여 rule을 표준국어대사전으로 적었다. 원문 대조 필요
- 문장 부호 판정은 `judgeFix`로 함께 처리한다(부호를 바꿔 끼우는 방식). 부호가 아예 빠진 문장(예: "밥 먹었니")은 wrongText가 비어 지금 형식으로 나타낼 수 없다. 1단계 문제를 만들 때 필요하면 다시 정한다
- 게임 화면에는 아직 연결하지 않았다(M3)
