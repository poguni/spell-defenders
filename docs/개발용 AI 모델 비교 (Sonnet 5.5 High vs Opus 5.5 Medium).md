# 개발용 AI 모델 비교: Sonnet 5.5 High vs Opus 5.5 Medium

> 작성일: 2026-10-09
> 대상: Claude Code로 「맞춤법 수비대」 같은 일반적인 웹 앱을 개발할 때 어떤 모델·effort 설정이 성능과 효율 면에서 나은지 비교
> 처음 답변 뒤 일정 조건이 바뀌어(촉박한 주말 완성 → 천천히 개발) **5장 추천을 고쳤습니다.**

---

## 1. 결론 요약

- 두 설정을 **직접 비교한 공식 측정 자료는 없습니다.** 아래 내용은 Anthropic 공식 문서의 가격표와 비용 최적화 자료에 근거한 추정입니다.
- **토큰 수는 Opus 5.5 Medium이 조금 적고, 비용은 Opus 쪽이 약 1.3~1.7배 더 들 것으로 추정합니다.**
- 천천히 개발하는 지금 일정에서는 **기본은 Sonnet 5.5 High, 어려운 부분만 Opus 5.5 Medium**을 추천합니다. (5장)

---

## 2. 확인된 사실 (공식 자료)

| 항목 | Sonnet 5.5 | Opus 5.5 |
|---|---|---|
| 가격 (100만 토큰당, 입력 / 출력) | $2 / $10 | $4 / $20 (2배) |
| 기본 effort | High | Medium |
| 공식 문서의 코딩 권장 | 코딩용으로 따로 권장하지 않음 | "대부분의 에이전트 작업은 **Opus 5.5 기본(medium)으로 시작**" |

- **Opus 5.5의 effort별 차이 (SWE-bench Pro 코딩 벤치마크)**: Medium은 High보다 점수가 약 2.5점 낮고 비용은 약 70%입니다. Low는 약 8점 낮고 비용은 약 3분의 1입니다.
- **두 모델의 직접 비교**: 지식 문제(GPQA Diamond)에서는 둘 다 91%로 같았습니다. 다만 Opus가 답한 문제만 보면 약 2점 앞섰습니다. **코딩에서 두 모델을 직접 비교한 결과는 공개되지 않았습니다.**

---

## 3. 성능과 효율 비교 (추정)

| 관점 | Sonnet 5.5 High | Opus 5.5 Medium |
|---|---|---|
| 일상적인 코딩 (화면, 컴포넌트, CSS) | 충분히 잘함 | 차이가 크지 않음 |
| 설계 판단, 어려운 버그, 여러 파일에 걸친 수정 | 생각을 많이 해서 보완 | 기본 능력이 더 높아 한 번에 맞힐 가능성이 큼 |
| 토큰당 비용 | 절반 | 2배 |
| 작업 하나에 드는 출력 토큰 | 많은 편 (High라서 생각을 길게 함) | 적은 편 (Medium이라 간결함) |

---

## 4. 토큰 사용량 대략 비교

아래는 **추정치**입니다. 실제 측정값이 아니고, 작업 내용에 따라 2~3배씩 달라질 수 있습니다.

Claude Code에서 "기능 하나 만들기"(예: 띄어쓰기 칼 화면)를 기준으로 하면:

| 항목 | Sonnet 5.5 High | Opus 5.5 Medium |
|---|---|---|
| 입력 토큰 (대부분 캐시에서 다시 읽음) | 약 50만~100만 | 약 40만~80만 (도구 호출이 적은 편) |
| 출력 토큰 (생각 + 코드) | 약 4만~8만 | 약 3만~6만 |
| 예상 비용 (API 기준) | 약 $0.8~1.5 | 약 $1.2~2.5 |

- **토큰 수는 Opus Medium이 조금 적고, 비용은 Opus가 약 1.3~1.7배 더 들 것으로 봅니다.** 토큰당 가격이 2배라서, 토큰을 덜 써도 그 차이를 다 메우지는 못합니다.
- **다시 고치는 일이 생기면 계산이 뒤집힙니다.** Sonnet이 한 번 잘못 만들어 수정하는 데 한 바퀴 더 돌면, 그 시점에 Opus보다 비싸집니다.
- **구독 플랜으로 Claude Code를 쓴다면** 달러 대신 사용량 한도로 생각하면 됩니다. Opus는 한도를 더 빨리 소진합니다.

## 5. 이 프로젝트에 추천하는 방식

### 5.1 처음 답변 (일정이 촉박하다는 전제)
처음에는 "주말 이틀 안에 완성"이 목표였기 때문에, 토큰보다 시간과 재작업이 더 비싸다고 보고 **Opus 5.5 Medium을 기본**으로 추천했습니다.

### 5.2 바뀐 추천 (천천히 개발)
일정이 촉박하지 않고, 업무 사이사이에 조금씩 개발해 수업 현장에 천천히 투입할 계획이므로 **재작업에 드는 시간 부담이 작아졌습니다.** 대신 오랜 기간 개발하면서 쌓이는 사용량(비용·구독 한도)이 더 중요해졌습니다.

| 작업 | 추천 설정 | 이유 |
|---|---|---|
| 화면 만들기, 컴포넌트, CSS, 문구 수정, 문제 JSON 정리 | **Sonnet 5.5 High** (기본) | 일상적인 코딩은 충분히 잘하고 비용은 절반 |
| 처음 프로젝트 구조 잡기, 정답 판정 로직, 게임 루프, 저장 구조 설계 | **Opus 5.5 Medium** | 처음에 잘 잡아야 나중에 고칠 일이 적은 부분 |
| Sonnet으로 두세 번 시도해도 안 잡히는 버그 | **Opus 5.5 Medium** → 그래도 안 되면 잠깐 High | 같은 실수를 반복하며 토큰을 쓰는 것보다 저렴 |

- 모델은 대화 중간에 바꾸지 말고 **새 작업(새 대화)을 시작할 때** 바꾸는 것이 좋습니다. 중간에 바꾸면 캐시가 처음부터 다시 쌓여 오히려 비용이 늘어납니다.
- Opus 5.5 High는 Medium보다 비용이 약 1.4배 들므로 막혔을 때만 잠깐 씁니다.
