- 작성일: 2026-10-12
- 버전: v2

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 맞춤법 수비대 (Spell Defenders) |
| 한 줄 소개 | 틀린 맞춤법을 들고 성으로 행진하는 "오타 몬스터"를 바르게 고쳐 정화하는 맞춤법·띄어쓰기 타워 디펜스 게임 |
| 대상 사용자 | 초등 2~6학년 학생(1단계 초2, 2단계 초3~4, 3단계 초5~6), 수업에 활용하는 담임·국어 교사 |
| 사용 기기 | 학생 디벗(크롬북, 1920×1080, 1366×768도 대응), 교실 전자칠판 |
| 배포 주소 | https://poguni.github.io/spell-defenders/ |
| 개발 기간 | 기획 2026-10-09 → 개발 2026-10-10 ~ 2026-10-12 (M1~M16) |
| 현재 상태 | 기획서의 핵심 기능(MVP, 교사 기능) 모두 구현. 세 단계 문제 200개 검수 완료. 첫 학교 테스트 준비 단계 |

## 2. 목표 및 배경

- 초등학생이 자주 틀리는 맞춤법(되/돼, 안/않, 로서/로써, 소리와 표기가 다른 낱말 등)과 띄어쓰기를 **반복 노출 + 즉각 피드백 + 아이 눈높이의 규칙 한 줄**로 익히게 한다.
- 설치·로그인 없이 **링크 하나로 시작**, 한 판이 **3~5분**이라 수업 마무리 10분이나 자투리 시간에 끼워 넣기 쉽다.
- 교사가 자기 반 학생이 자주 틀리는 문장을 **AI로 빠르게 문제로 만들어 학생 기기에 나눠 줄 수 있다.**
- 파일럿: 5학년 우리 반, 2학기 국어·창체 시간, 사전·사후 간이 평가(20문항)로 효과 확인.
- 일정 원칙: 마감 없이 **작은 단위(마일스톤) 하나씩** 개발하고, 단위마다 실행 가능한 상태와 진행 기록(`docs/진행 기록.md`)을 남긴다. 단계가 큰 일(1단계, 2단계, 기록 내보내기)은 먼저 계획 문서를 만들고 추천안을 확인받은 뒤 진행한다.

## 3. 주요 기능

**학생 — 개인 수비 모드 (세 단계)**

| 단계 | 대상 | 문제 | 고치는 방식 | 한 판 |
|---|---|---|---|---|
| 1단계 마을 | 초2 | 60 (유형 6) | 틀린 곳이 표시된 채로 보기 2개, 문장 부호 빈칸, 띄어쓰기 칼. 글자를 더 크게 | 8문제, 웨이브 2개, 60초, 빨라지지 않음 |
| 2단계 숲 | 초3~4 | 60 (유형 6) | 틀린 낱말 찾기 → 보기 3개(엉뚱한 낱말은 한 번 더 기회), 띄어쓰기 칼 | 10문제, 웨이브 3개, 50초, 0.95배 |
| 3단계 성 | 초5~6 | 80 (유형 9) | 2단계 방식 + "고칠 곳 없음" 버튼, 띄어쓰기 칼 | 10문제, 웨이브 3개, 45초, 0.9배 |

- 3레인 실시간 수비전, 속도 조절(보통/느리게/일시정지), 누른 몬스터만 멈춤, 틀린 몬스터만 남으면 "건너뛰기"
- 맞히면 **수비대원 정화 연출**(깃펜에서 몬스터로 빛줄기 → 몬스터 정화 → 약 1초 뒤 설명 창). 틀리면 바로 설명 창(바른 문장, 규칙 한 줄, 띄어쓰기는 틀린 곳 빨간색)
- 결과(별 1~3개), **낙서 지우기**(시간 제한 없는 복습), **오답 노트**, **간격 반복**(오답이 다음 스테이지에 최대 3개 섞임, 3번 연속 정답이면 "익힘"), **몬스터 도감**(21종)
- 단계 선택(돌아가기 버튼: 처음으로·지도로), 스테이지 지도(단계마다 태그 묶음 스테이지 + 모두 섞기), 닉네임(선택), 효과음 켜기/끄기

**학생 — 내 기록**
- **성적표**: 단계별 스테이지 별, 익힌 유형, 도감 n / 21, 오답 노트 수, 날짜. 화면 캡처 한 장에 들어감
- **내 기록 저장하기·불러오기**: 기록을 `.json` 파일로 저장, 다른 기기에서 불러오기(지금 기록 / 파일 기록을 나란히 보여 주고 확인)
- **내 기록 지우기**: 저장하고 지우기 / 지우기 / 그만두기

**교사 — 학급 수비전(전자칠판)**
- 단계·유형·몬스터 수(5/10/15) → 한 마리씩 크게, 시간 제한 없이 → 학급 점수. 학생 기록을 바꾸지 않음

**교사 — 교사 메뉴(PIN)**
- OpenRouter API 키 입력·연결 확인·모델 선택, **AI 문제 생성 → 자동 검증 → 교사 승인·수정**, 세트별 출제 켜기/끄기(단계별 보기 개수·주의점이 생성 지침에 반영됨)
- **나눠 주기**: 공유 링크, QR(작은 세트), JSON 파일 → 학생 기기의 "선생님 문제" 스테이지
- 교사용 안내(`docs/교사용 안내.md`·`.html`): 단계별 유형·스테이지 표, 5학년 2학기 단원 연결표, 학년별 수업 활용 예시, 학생 기록 지키기, 사전·사후 평가지

**콘텐츠**
- 내장 문제 200개(1단계 60, 2단계 60, 3단계 80), 모두 교사 검수 완료
- 몬스터 21종 × 오타·정화 그림 42장, 배경 4장(마을, 숲, 성, 시작 화면), 모두 나노바나나로 제작

## 4. 기술 스택 및 아키텍처

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 18.3 + Vite 6.4 + TypeScript 5.9 | 서버 없는 정적 사이트, 빠른 개발 서버 |
| 게임 화면 | DOM + CSS 애니메이션 + `requestAnimationFrame` | 한글 문장이 핵심이라 Canvas보다 글자 표시·터치·접근성에 유리 |
| 화면 크기 | 1920×1080 고정 좌표 무대를 통째로 확대·축소 | 크롬북·노트북·전자칠판에서 같은 배치 |
| 단계별 차이 | 게임 수치 `STAGE_SETTINGS`, 보기 개수 `CHOICE_COUNT`, 글자 크기 `.level-1` | 한 엔진으로 학년별 난이도를 다르게 |
| 저장 | localStorage(학생 기록, 교사 데이터, 불러온 세트를 따로), API 키는 기본 sessionStorage | 로그인·서버 없음, 개인정보 수집 안 함 |
| 기록 파일 | `format: spell-defenders-record` JSON, 버전·마이그레이션 | 서버 없이 기록 백업·이동 |
| AI | 브라우저에서 OpenRouter 직접 호출, strict JSON 스키마 | 키는 사용자가 앱 화면에서만 입력 |
| 공유 | 브라우저 내장 deflate(`CompressionStream`) + base64url, 주소 `#set=` | 서버 없이 전달 |
| QR | `qrcode` 1.5.4 (나눠 주기 화면에서만 로드) | 첫 화면 용량 유지 |
| 효과음 | Web Audio API | 소리 파일 없음 |
| 글꼴 | Pretendard (dynamic subset) | 가독성, 필요한 글자 조각만 다운로드 |
| 테스트 | Vitest 5.0(단위), Playwright 1.64(화면 흐름) | 정답 판정 오류 방지가 최우선 |
| 배포 | GitHub Pages + GitHub Actions | 무료, 비밀 값 없음 |

**폴더 구조**

```
src/
  judge/     정답 판정·정규화·문제 검증, 단계별 태그·길이·보기 개수 (순수 함수)
  game/      스테이지 상태·단계별 수치, 게임 루프, 출제, 학습 규칙(간격 반복·익힘), 스테이지 지도, 효과음
  storage/   학생 기록(엄격한 읽기 포함), 기록 파일, 교사 데이터·API 키, 불러온 세트
  ai/        생성 지침·스키마, OpenRouter 요청, 응답 → 문제 변환
  share/     공유 코드(압축·검사), QR, 파일 내려받기
  components/ 무대, 문장 카드, 띄어쓰기 칼, 설명 창(정답 때 늦게 나타남), 그림
  screens/   화면 18개 (시작, 단계 선택, 지도, 수비전, 결과, 낙서 지우기, 오답 노트, 도감, 내 기록,
             학급 준비·수비전, 교사 PIN·메뉴·키 설정·생성·세트, 나눠 주기, 불러오기)
  data/      내장 문제 JSON 6개, 태그별 몬스터 이름·규칙(21개)
scripts/validate-problems.ts   문제 파일 검증 (npm run validate)
e2e/                           Playwright 화면 테스트
```

**핵심 흐름**: 문제 JSON → `validate.ts`(같은 검증을 내장·AI·공유 문제에 모두 적용, 단계별 길이·보기 개수 포함) → `pool.ts`(승인한 문제만) → `stages.ts`/`progress.ts`(스테이지 구성 + 오답 섞기) → `stage.ts`(단계별 수치를 담은 순수 상태 함수) ← `useGameLoop.ts`(시간 흐름) → 화면. 기록은 `save.ts` ↔ localStorage, `recordFile.ts` ↔ 파일.

## 6. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| 서버·로그인 없이 기기 저장만 | 학생 개인정보를 모으지 않고 운영 부담 없이 링크 하나로 쓰기 위해. 대신 기록 백업은 파일로 |
| Canvas 대신 DOM, 1920×1080 고정 무대 | 한글 문장 렌더링·터치가 쉽고, 모든 기기에서 배치가 같으며 "실제 글자 크기"를 테스트로 잴 수 있음 |
| `reviewed: true` 문제만 출제 | 잘못된 맞춤법을 가르치는 것이 가장 치명적이라 내장·AI·공유 문제 모두 교사 승인 |
| 한 문장에 틀린 곳 한 군데 | 판정·설명을 단순하고 확실하게. 그래서 "할꺼야 → 할 거야", "안했다 → 안 했다"처럼 띄어쓰기까지 바뀌는 예는 문제에서 뺌 |
| 두 답이 모두 맞는 문장은 넣지 않음 | 보조 용언, 아라비아 숫자 + 단위(제43항 다만), 조사·의존 명사가 둘 다 되는 '만큼·대로·뿐·밖에', 두 뜻이 다 되는 문장("숙제를 잃어버렸다/잊어버렸다"), 감탄문의 마침표·느낌표 |
| 보기 개수를 단계별로 검증(1단계 2, 2단계 3) | 기획서 7.4를 사람 손이 아니라 검증 모듈이 지키게. 세 번째 보기에 사실은 맞는 말("되어요", "아니")이 섞이지 않게 함 |
| 단계별 게임 수치(`STAGE_SETTINGS`) | 2학년은 읽는 시간이 더 필요. 3단계 수치는 그대로 두고 1·2단계만 느리게. 선생님 문제처럼 섞이면 쉬운 단계에 맞춤 |
| 1단계만 글자를 키움 | 1단계 문장은 15자 이하라 여유가 있음. 2단계는 25자까지라 3단계와 같은 크기 |
| 단계마다 새 몬스터(겹치지 않는 동물) | 도감이 태그마다 한 장이라 같은 그림이 두 번 나오면 헷갈림. 모양으로 유형을 표현(예: 털이 엉긴 양 → 띄어쓰기, 등에서 떨어진 아기 개구리 → 조사 붙여 쓰기) |
| 정답 때 설명 창을 1초 늦게(CSS) | 수비대원 동작이 설명 창에 가려 보이지 않던 문제. 타이머 대신 CSS 애니메이션이라 "계속하기"는 바로 눌러도 되고 테스트도 바뀌지 않음. 움직임 줄이기 설정이면 연출 없음 |
| 기록 불러오기는 통째로 바꾸기 | 합치기는 오답 노트·연속 정답 처리가 애매하고 학생이 결과를 예상하기 어려움. 대신 두 기록을 나란히 보여 주고 확인 |
| 기록 파일에 교사 데이터는 넣지 않음 | 학생 파일에 PIN·API 키·문제 세트가 섞이면 안 됨 |
| 엄격한 기록 읽기를 따로 둠 | 앱 시작 때는 깨진 기록이면 빈 기록으로 조용히 시작하지만, 파일 불러오기에서 그러면 기록이 지워진 것처럼 보임 |
| "내 기록" 화면에 기록 관련 기능을 모음 | 시작 화면 아래 버튼이 5개가 되는 것을 피하고, 학생이 찾기 쉽게 |
| 큰 단위는 계획 문서 → 추천안 확인 → 진행 | 천천히 개발하는 원칙. 선생님이 결정할 것(수치, 묶음, 몬스터 이름)을 먼저 정리 |

## 7. 문제 해결 기록

| 문제 | 해결 |
|---|---|
| Vite 기본 템플릿이 React 19, Vitest 3.2 보안 권고 | React 18.3 직접 구성, Vitest 5.0.3 |
| 탭을 비웠다 돌아오면 몬스터가 한꺼번에 뜀 | 한 프레임 최대 0.1초 |
| Playwright 병렬 실행 중 개발 환경이 꺼짐 | `--workers=1`, 테스트 전용 포트 |
| 배경 그림의 길(2줄)과 게임 레인(3줄)이 다름 | 반투명 흙길 3줄을 덧그림(마을·숲 배경에서도 몬스터가 잘 보여 유지) |
| 30문제 공유 코드가 QR에 안 들어감 | 링크 중심, 30문제 초과는 파일로 |
| 1단계를 열자 "준비 중" 화면 테스트가 깨짐, 세 단계가 다 열리자 확인할 단계가 없어짐 | 개발 스위치로 3단계 문제 하나만 남겨 1·2단계가 "준비 중"이 되는지 확인 |
| 웨이브의 마지막 몬스터를 정화하면 바로 사라져 정화 모습·테스트 확인이 안 됨 | 설명 창이 떠 있는 동안 그 몬스터를 계속 그림. 운에 따라 실패하던 1단계 테스트도 함께 고침 |
| 맞혀도 수비대원 동작이 설명 창에 가림 | 빛줄기·빛 터짐·수비대원 빛남 연출 후 설명 창이 나타나게 |
| 지도에서 "단계 바꾸기"로 가면 나갈 길이 없음(브라우저 이전도 비활성) | 단계 선택에 "처음으로"·"지도로" 버튼 |
| 기록 파일을 "문제 파일 불러오기"에 넣거나 그 반대 | 서로 형식을 알아보고 "어디서 불러오세요"라고 안내 |
| 가장 긴 성적표에서 제목 막대가 눌림 | 간격 조정, 제목 막대가 줄어들지 않게 하고 테스트로 높이 확인 |
| 문제 문장 중 띄어쓰기가 확실하지 않은 것("소풍 날"), 근거 조항이 맞지 않는 것(안/않 제39항) | 다른 문장으로 바꾸고, 근거를 표준국어대사전으로 |

## 8. 보안·성능 고려사항

**보안**
- API 키는 코드·`.env`·저장소·배포 설정 어디에도 없음. 키는 `https://openrouter.ai/api/v1`로만, Authorization 머리글로만 전송. `fetch`는 한 곳.
- 교사 PIN은 SHA-256 해시로만 저장(클라이언트 쪽 보호라는 점을 화면에 안내).
- 공유 코드는 주소의 `#` 뒤라 서버로 보내지지 않음. 받을 때 길이·풀린 크기 상한, 문제마다 다시 검증, 승인 전 문제 버림.
- 기록 파일: 1MB 상한, 형식·버전 검사, 칸별 검사(이상한 칸만 기본값), 글자로만 읽음. 학생 기록만 담고 교사 데이터는 담지 않음.

**성능(학교 와이파이 고려)**
- 첫 화면 JS 약 89KB(압축) + CSS + 글꼴 조각. 그림은 WebP, 몬스터 한 장 40~90KB.
- QR 라이브러리는 나눠 주기 화면에서만 로드.

## 11. 알려진 한계

- **현장 확인 전**: 학생 디벗 접속·QR, 전자칠판 가독성, 크롬북에서 기록 파일 저장·다른 디벗에서 불러오기, 첫 학교 테스트는 아직 하지 않았다. 게임 수치(속도, 문제 수, 별 기준)와 정화 연출 길이는 추정값이다.
- **서버가 없어** 교사가 반 전체 기록을 모아 볼 수 없다. 기록 백업은 학생이 파일을 저장해 두어야 한다(파일을 잃어버리면 소용없음).
- **브라우저 "이전" 버튼**은 쓸 수 없다(앱이 주소 하나로 움직임). 화면 안의 돌아가기 버튼만 있다.
- **PIN은 클라이언트 쪽 보호**라 기술적으로는 우회할 수 있다.
- 공유 링크는 30문제까지, QR은 약 5문제까지. 학생 기기는 선생님 문제 세트를 한 번에 하나만 갖고, 지우는 버튼이 없다.
- 배경 그림의 길(2줄)과 레인(3줄)이 맞지 않아 흙길을 덧그렸다. 시작 화면 그림에 작은 반짝이 표시(✦)가 있다.
- AI 검증 오류 문구가 조금 기술적이고, AI 문제가 내장 문제와 같은 문장인지는 검사하지 않는다.
- 평가지 문장이 앱 안에도 있어 사후 평가 전에 학생이 볼 수 있다.
- 성취기준 번호를 고시 원문과 대조하지 않았고, 1·2단계는 교과서 단원 연결표가 없다.

## 12. 향후 개선 아이디어 / 업데이트 계획

**다음에 하면 좋을 것 (파일럿 준비)**
1. **첫 학교 테스트**(`docs/첫 학교 테스트 안내.md`) → 관찰 기록으로 조정: 단계별 몬스터 속도·문제 수, 별 기준, 글자 크기, 안내 문구, 정화 연출 길이
2. **현장 기기 확인**: 디벗에서 기록 파일 저장 위치, 구글 드라이브로 옮겨 다른 디벗에서 불러오기, 전자칠판 가독성
3. **"문제 신고" 버튼**: 기획서 13장 위험 대응에 있으나 아직 없음. 학생이 이상한 문제를 표시하고, 기록 파일처럼 파일로 선생님께 전달
4. **AI 모델 3종 비교**: 같은 지침으로 20개씩 생성해 단계별 제외율 비교 → 기본 모델 확정(기획서 14.3 남은 질문)
5. 성취기준 원문 대조, 1·2학년군·3~4학년군 교과서 단원 연결표

**여유 있으면**
- 브라우저 "이전" 버튼 지원(화면마다 브라우저 기록 남기기, 수비전 중에는 "그만할까요?" 확인)
- 학생 기기에서 불러온 선생님 문제 세트 지우기·여러 세트 보관
- AI 검증 오류를 교사용 쉬운 말로, 내장 문제와 같은 문장 걸러 내기
- 3레인에 맞춘 배경 그림 다시 만들기, 시작 화면 그림의 ✦ 지우기
- PWA 오프라인(그림이 많아 캐시 효과가 큼)
- 성적표에 "가장 많이 틀린 유형"과 그 규칙 카드 한 장(다음에 연습할 것을 알려 줌)
- 기록 파일을 저장한 지 오래되면(예: 7일) 처음 화면에서 저장을 한 번 권하기

**확장 (파일럿 결과를 보고 결정)**
- 반 전체 기록 모으기: 학생 기록 파일 여러 개를 교사 기기에서 불러와 유형별 정답률 표(서버 없이)
- 5~6학년용 **직접 입력 모드**(한글 입력기 조합 중 판정 안 함)
- 문장 읽어주기(TTS, 1단계 우선)
- 모둠 협동 수비 모드, "변장 몬스터"(바른 문장을 든 주민은 공격하지 않는 판별 유형)
- 3단계 '보조 용언' 태그(두 답을 모두 정답으로 받는 문제 형식이 필요)
