# 맞춤법 수비대 개발 보고서 (v1)

- 작성일: 2026-10-11
- 버전: v1
- 기준 커밋: `5f84734` 시작 화면 배경 그림 적용

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 맞춤법 수비대 (Spell Defenders) |
| 한 줄 소개 | 틀린 맞춤법을 들고 성으로 행진하는 "오타 몬스터"를 바르게 고쳐 정화하는 맞춤법·띄어쓰기 타워 디펜스 게임 |
| 대상 사용자 | 초등 학생(MVP 콘텐츠는 3단계, 5~6학년), 수업에 활용하는 담임·국어 교사 |
| 사용 기기 | 학생 디벗(크롬북, 1920×1080, 1366×768도 대응), 교실 전자칠판 |
| 배포 주소 | https://poguni.github.io/spell-defenders/ |
| 개발 기간 | 기획 2026-10-09 → 개발 2026-10-10 ~ 2026-10-11 (M1~M8) |

## 2. 목표 및 배경

- 초등학생이 자주 틀리는 맞춤법(로서/로써, 웬/왠, 맞히다/맞추다 등)과 띄어쓰기를 **반복 노출 + 즉각 피드백 + 아이 눈높이의 규칙 한 줄**로 익히게 한다.
- 설치·로그인 없이 **링크 하나로 시작**, 한 판이 **3~5분**이라 수업 마무리 10분이나 자투리 시간에 끼워 넣기 쉽다.
- 교사가 자기 반 학생이 자주 틀리는 문장을 **AI로 빠르게 문제로 만들어 학생 기기에 나눠 줄 수 있다.**
- 파일럿: 5학년 우리 반, 2학기 국어·창체 시간, 사전·사후 간이 평가(20문항)로 효과 확인.
- 일정 원칙: 마감 없이 **작은 단위(마일스톤) 하나씩** 개발하고, 단위마다 실행 가능한 상태와 진행 기록(`docs/진행 기록.md`)을 남긴다.

## 3. 주요 기능

**학생 — 개인 수비 모드**
- 3레인 실시간 수비전: 몬스터가 문장을 들고 걸어오고, 눌러서 고치면 정화된다. 속도 조절(보통/느리게/일시정지), 누른 몬스터만 멈춤.
- 고치는 방식 3가지: 틀린 낱말 찾기 → 보기 고르기 / "고칠 곳 없음" 버튼 / **띄어쓰기 칼**(글자 사이를 눌러 띄움·붙임 → 자르기)
- 정답·오답마다 바른 문장과 규칙 한 줄 설명, 띄어쓰기 오답은 틀린 곳을 빨간색으로 강조
- 결과 화면(별 1~3개), **낙서 지우기**(틀리거나 놓친 문제를 시간 제한 없이 복습)
- **오답 노트**(태그별 규칙 카드), **간격 반복**(오답이 다음 스테이지에 최대 3개 섞임, 같은 태그 3번 연속 정답이면 "익힘"), **몬스터 도감**
- 단계 선택·스테이지 지도, 닉네임(선택), 효과음 켜기/끄기, 내 기록 지우기
- 틀린 몬스터만 남으면 "건너뛰기"

**교사 — 학급 수비전(전자칠판)**
- 단계·유형(여러 개)·몬스터 수(5/10/15) 고르기 → 한 마리씩 크게, 시간 제한 없이 → 학급 점수
- 글자 크기 개인 모드의 2배, 학생 기록을 바꾸지 않음

**교사 — 교사 메뉴(PIN)**
- OpenRouter API 키 입력·연결 확인·모델 선택(Sonnet 5.5 기본 / Gemini 3.8 Flash / GPT-6 Luna / 직접 입력)
- **AI 문제 생성 → 자동 검증 → 교사 승인·수정**, 문제 세트별 출제 켜기/끄기
- **나눠 주기**: 공유 링크, QR(작은 세트), JSON 파일 → 학생 기기에서 "선생님 문제" 스테이지로 불러오기
- 교사용 안내 문서(`docs/교사용 안내.md`·`.html`): 단원 연결표, 수업 활용 예시, 사전·사후 평가지 20문항씩

**문제 콘텐츠**
- 내장 3단계 문제 80개(교사 검수 완료) + 1단계 임시 문제 2개(검수 전, 개발 모드에서만)
- 3단계 태그 9개 × 몬스터 9종, 모두 나노바나나로 그린 그림

## 4. 기술 스택 및 아키텍처

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 18.3 + Vite 6.4 + TypeScript 5.9 | 서버 없는 정적 사이트, 빠른 개발 서버. Vite 기본 템플릿은 React 19라 직접 구성 |
| 게임 화면 | DOM + CSS 애니메이션 + `requestAnimationFrame` | 한글 문장이 핵심이라 Canvas보다 글자 표시·터치·접근성에 유리 |
| 화면 크기 | 1920×1080 고정 좌표 무대를 통째로 확대·축소 | 크롬북·노트북·전자칠판에서 같은 배치 |
| 저장 | localStorage(학생 기록, 교사 데이터, 불러온 세트를 따로), API 키는 기본 sessionStorage | 로그인·서버 없음, 개인정보 수집 안 함 |
| AI | 브라우저에서 OpenRouter 직접 호출, strict JSON 스키마 | 키는 사용자가 앱 화면에서만 입력 |
| 공유 | 브라우저 내장 deflate(`CompressionStream`) + base64url, 주소 `#set=` | 서버 없이 전달, 라이브러리 불필요 |
| QR | `qrcode` 1.5.4 (나눠 주기 화면에서만 지연 로드) | 첫 화면 용량 유지 |
| 효과음 | Web Audio API | 소리 파일 없음 |
| 글꼴 | Pretendard (dynamic subset) | 가독성, 필요한 글자 조각만 다운로드 |
| 테스트 | Vitest 5.0(단위), Playwright 1.64(화면 흐름) | 정답 판정 오류 방지가 최우선 |
| 배포 | GitHub Pages + GitHub Actions | 무료, 비밀 값 없음 |

**폴더 구조**

```
src/
  judge/     정답 판정·정규화·문제 검증 (순수 함수)
  game/      스테이지 상태, 게임 루프, 출제, 학습 규칙(간격 반복), 스테이지 지도, 효과음
  storage/   학생 기록, 교사 데이터·API 키, 불러온 세트
  ai/        생성 지침·스키마, OpenRouter 요청, 응답 → 문제 변환
  share/     공유 코드(압축·검사), QR
  components/ 무대, 문장 카드, 띄어쓰기 칼, 설명 창, 그림
  screens/   화면 17개 (시작, 단계 선택, 지도, 수비전, 결과, 낙서 지우기, 오답 노트, 도감,
             학급 준비·수비전, 교사 PIN·메뉴·키 설정·생성·세트, 나눠 주기, 불러오기)
  data/      내장 문제 JSON, 태그별 몬스터 이름·규칙
scripts/validate-problems.ts   문제 파일 검증 (npm run validate)
e2e/                           Playwright 화면 테스트
```

**핵심 흐름**: 문제 JSON → `validate.ts`(같은 검증을 내장 문제·AI 문제·공유 받은 문제에 모두 적용) → `pool.ts`(승인한 문제만) → `stages.ts`/`progress.ts`(스테이지 구성 + 오답 섞기) → `stage.ts`(순수 상태 함수) ← `useGameLoop.ts`(시간 흐름) → 화면.

## 6. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| 서버·로그인 없이 기기 저장만 | 학생 개인정보를 모으지 않고, 운영 부담 없이 링크 하나로 쓰기 위해. 대신 교사 대시보드는 없음 |
| Canvas 대신 DOM | 게임의 중심이 한글 문장이라 글자 렌더링·줄바꿈(`keep-all`)·터치 영역 관리가 쉬움 |
| 1920×1080 고정 무대를 확대·축소 | 디벗·노트북·전자칠판에서 배치가 같고, 테스트에서 "실제 글자 크기"를 계산해 검사 가능 |
| 맞춤법은 MVP에서 선택형만 | 저학년 입력 부담과 한글 입력기 조합 문제를 피함. 판정 함수는 직접 입력도 받을 수 있게 설계 |
| `reviewed: true` 문제만 출제 | 잘못된 맞춤법을 가르치는 것이 가장 치명적인 위험이라, 내장·AI·공유 문제 모두 교사 승인을 거침 |
| '보조 용언' 태그 제외 | 띄어쓰기 두 가지가 모두 허용되어 오답 처리 위험 |
| AI에게 틀린 글자만 받고 위치는 앱이 찾음 | AI가 글자 위치(`start`)를 자주 틀리게 셈. id·`acceptedAnswers`·`source`도 앱이 채움 |
| API 키 기본 sessionStorage | 공용 기기에 키가 남지 않게. "이 기기에 저장"을 직접 고를 때만 localStorage |
| 익힘은 수비전 정답만 셈 | 시간 제한 없는 복습에서 맞힌 것까지 세면 너무 쉽게 익힘 판정됨 |
| 오답 노트에는 실제로 틀린 문제만 | 성에 닿아 놓친 문제는 읽지 못한 것일 수 있어 낙서 지우기에서 먼저 다시 풀게 함 |
| 건너뛰기해도 낙서·성벽 감소 | 건너뛰기로 별을 지키는 꼼수를 막음 |
| 공유는 링크 중심, QR은 작은 세트만 | 한글은 압축이 잘 안 돼 30문제가 QR 한 장에 안 들어감. 5문제도 QR 버전 20 |
| `lz-string` 대신 내장 deflate | 측정 결과 약 20% 짧고 라이브러리가 필요 없음 |
| 모양이 틀린 문제가 하나라도 있으면 세트 전체 거부 | 조작된 링크를 일부만 받아들이는 애매한 상태를 만들지 않기 위해 |
| 공유 문제 id를 받는 쪽에서 내용 해시로 | 같은 세트를 다시 받아도 별·오답 노트가 이어지고 내장 id와 겹치지 않음 |
| 효과음은 소리 파일 없이 Web Audio | 용량과 저작권 걱정 없음 |
| 개발: 구조·판정은 Opus, 일상 작업은 Sonnet | `docs/개발용 AI 모델 비교` 5.2. 처음에 잘 잡아야 하는 부분에 더 강한 모델 |

## 7. 문제 해결 기록

| 문제 | 해결 |
|---|---|
| Vite 기본 템플릿이 React 19 | 기획대로 React 18.3으로 직접 구성 |
| Vitest 3.2에 보안 권고 | 5.0.3으로 올려 `npm audit` 0건 |
| 몬스터 말풍선 글자가 1366×650에서 약 18px로 작음 | 말풍선은 앞 8글자 + '…'만 크게(실제 약 25px), 전체 문장은 문장 카드에서 읽게 함 |
| 탭을 비웠다 돌아오면 몬스터가 한꺼번에 뜀 | 게임 루프에서 한 프레임 최대 0.1초로 제한 |
| Playwright 병렬 실행 중 Claude Code가 두 번 꺼짐 | `--workers=1`로 하나씩 실행, 테스트 전용 포트 5179 + 기존 서버 재사용 안 함 |
| 배경 그림의 길은 2줄인데 게임은 3레인 | 반투명 흙길 3줄을 덧그림(배경 다시 만들기는 현장 테스트 뒤 결정) |
| 몬스터가 성·수비대원과 겹침 | 몬스터 170px, 말풍선 아래로 끌어올리고 길 끝을 앞당김 |
| GitHub Pages 하위 경로에서 그림 경로 | `base: './'` + `import.meta.env.BASE_URL` 기준 경로, `/spell-defenders/` 아래에서 직접 열어 확인 |
| 학급 모드 띄어쓰기 오답 설명 창이 화면을 118px 넘침 | "내가 자른 문장"만 104px → 64px |
| 틀린 몬스터가 성에 닿을 때까지 기다려야 다음 웨이브 | `canSkip`/`skipFailed`와 "건너뛰기" 버튼 |
| 30문제 공유 코드가 QR에 안 들어감 | 링크 중심, 30문제 초과는 JSON 파일로 |
| 작은 코드가 거대하게 풀리는 공격(압축 폭탄) | 코드 길이·풀린 크기 상한 |
| 개발 모드에서 초기값이 두 번 계산되어 공유 주소 처리가 꼬임 | 주소는 처음 한 번만 읽고, 읽은 뒤 `#set=`을 지움 |
| 시작 화면 버튼이 배경 그림의 몬스터 행렬·성을 가림 | 그림 속 제목을 그대로 쓰고 글자 제목은 화면 읽기용으로만, 버튼은 빈 잔디밭으로 옮김 |

## 8. 보안·성능 고려사항

**보안**
- API 키는 코드·`.env`·저장소·배포 설정 어디에도 없음. 키는 `https://openrouter.ai/api/v1`로만, Authorization 머리글로만 전송. `fetch`는 `src/ai/openrouter.ts` 한 곳.
- 저장한 키는 화면에 다시 보여 주지 않음, 비밀번호 형식 입력, 키 지우기, OpenRouter 사용 한도 설정 안내.
- 교사 PIN은 SHA-256 해시로만 저장. 클라이언트 쪽 보호(학생의 우연한 접근 방지 수준)라는 점을 화면에 안내.
- 공유 코드는 주소의 `#` 뒤라 서버로 보내지지 않음. 받을 때 길이·풀린 크기 상한, 문제마다 다시 검증, 승인 전 문제 버림, 세트 이름 30자.
- 마일스톤마다 저장소와 `dist/`에서 키 모양 문자열 검사, 빌드 JS의 외부 주소가 openrouter.ai뿐인지 확인. `npm audit` 0건.

**성능(학교 와이파이 고려)**
- 첫 화면: JS 약 80KB + CSS 약 17KB(압축) + 글꼴 조각 약 180KB.
- 3단계 수비전까지 약 1.8MB(그림은 WebP). QR 라이브러리 10KB는 나눠 주기 화면에서만 로드.

## 11. 알려진 한계

- **서버가 없어** 교사가 학생 기록을 모아 볼 수 없고, 브라우저 데이터를 지우면 진도가 사라진다(기록 내보내기 미구현).
- **PIN은 클라이언트 쪽 보호**라 기술적으로는 우회할 수 있다.
- **콘텐츠가 3단계 위주**: 1·2단계는 문제가 없어(1단계 임시 2개뿐) "준비 중"으로 나온다.
- 공유 링크는 30문제까지, QR은 약 5문제까지. 학생 기기는 한 번에 한 세트만 갖고, 지우는 버튼이 없다.
- 배경 그림의 길(2줄)과 게임 레인(3줄)이 맞지 않아 흙길을 덧그렸다.
- 시작 화면 그림 오른쪽 아래에 생성 도구의 작은 반짝이 표시(✦)가 있다.
- AI 검증 오류 문구가 검증 모듈 문구 그대로라 조금 기술적이다(예: "choices 중 정답이 0개임").
- AI 생성 문제가 내장 문제와 같은 문장인지는 검사하지 않는다.
- 평가지 문장이 앱 안에도 있어 사후 평가 전에 학생이 볼 수 있다.
- **현장 확인 전**: 디벗에서 배포 주소 접속·QR 찍기, 전자칠판에서 교실 뒤까지 읽히는지, 첫 학교 테스트는 아직 하지 않았다.
- 성취기준 번호를 국가교육과정정보센터 고시 원문과 대조하지 않았고, 단원 연결표의 학습 내용은 단원명으로 짐작한 것이다.

## 12. 향후 개선 아이디어 / 업데이트 계획

**다음에 하면 좋을 것 (파일럿 준비)**
1. **현장 확인**: 디벗에서 배포 주소 열기·한 스테이지 완료, QR·링크로 세트 불러오기, 전자칠판 가독성 → 기획서 10장 "현장 테스트 반영"
2. **첫 학교 테스트(10~15분)** 뒤 게임 수치 조정: 몬스터 속도, 성벽 감소, 별 기준(`src/game/stage.ts` 맨 위)
3. **AI 모델 3종 비교**: 같은 지침으로 20개씩 생성해 오류율 비교 → 기본 모델 확정(기획서 14.3 남은 질문)
4. **기록 내보내기·불러오기**: 서버가 없어 기록 유실이 가장 큰 운영 위험. 화면 캡처용 "성적표"도 함께(기획서 6.2)
5. 성취기준 번호 원문 대조, 2단원(올바른 문장으로 글을 써요) 실제 학습 내용 확인 → 필요하면 문제 유형 추가

**여유 있으면**
- **"문제 신고" 버튼**: 기획서 13장 위험 대응에 있으나 아직 없음. 학생이 이상한 문제를 표시하면 교사 기기로 가져올 방법(파일)과 함께
- AI 검증 오류·제외 이유를 교사용 쉬운 말로 바꾸기
- 내장 문제와 같은 문장인 AI 문제 걸러 내기
- 학생 기기에서 불러온 "선생님 문제" 세트 지우기 버튼, 여러 세트 보관
- 3레인에 맞춘 배경 그림 다시 만들기, 시작 화면 그림의 ✦ 표시 지우기
- PWA 오프라인(학교 와이파이 불안정 대비) — 그림이 약 4MB라 캐시 효과가 큼
- 학급 수비전에서 정답 뒤 "왜 그럴까?" 토론용 잠깐 멈춤 화면

**확장 (파일럿 결과를 보고 결정)**
- 1·2단계 문제은행과 몬스터 확장(각 20문제 샘플부터), 1단계 문장 부호 정식 문제
- 5~6학년용 **직접 입력 모드**(한글 입력기 조합 중 판정 안 함)
- 문장 읽어주기(TTS, Web Speech API)
- 모둠 협동 수비 모드(한 기기 화면 나누기부터)
- "변장 몬스터": 바른 문장을 든 주민은 공격하지 않는 판별 유형
- 태그별 정답률을 기기 안에서 보여 주는 학생용 "나의 약점" 화면
